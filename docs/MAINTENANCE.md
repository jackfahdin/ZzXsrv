# 本地维护路线与关注事项

更新日期：2026-09-09。

## 维护目标和边界

先维护一个自己能够长期使用、能够解释构建过程和定位故障的 Windows 版本。当前只在本地保存代码、提交和验证记录；远程仓库由维护者另行处理，不执行 push、远程发布或远程 CI 配置。

本地历史已采用 `upstream`（原作者 VcXsrv 快照）与 `master`（我们的开发）两层结构。来源与版权说明见 [FORK.md](../FORK.md)，同步步骤、组件来源和更新优先级见 [上游更新规则](UPSTREAM.md)。完整旧历史另有归档，旧构建报告及标签保留原提交号。

首个支持目标是 Windows x64 Release。构建使用 PowerShell、VS2022/MSVC 和原生 Windows 辅助工具，不依赖 WSL/Cygwin，不自动下载或安装工具。Python 下限为 3.11。源码路径保持无空格；已有工具路径含空格的测试继续保留。

当前已验证基线提交为 `a4adc3dc3f2158c2308133cecee19a71cf62bcc8`，本地标签为 `local-baseline-20260909-a4adc3dc`。已完成新 worktree 中的完整构建、43 项测试（无跳过）、35 个 PE 的依赖检查与经认证的本地 TCP X 根窗口查询。详情见 [实际验证报告](validation/2026-09-09-baseline.md)。这不代表多机兼容性或完整应用兼容性已经完成。

## 验证层次

| 层次 | 验证内容 | 能证明什么 | 不能替代什么 |
| --- | --- | --- | --- |
| 脚本测试 | 路径、退出码、环境恢复、生成数据、运行目录整理 | 被测试的脚本行为符合预期 | 实际编译、GUI 使用 |
| 干净检出构建 | 新目录、固定提交、现有工具、All 阶段 | 不依赖旧工作目录中的未跟踪中间产物 | 全部第三方库均由源码构建、二进制逐字节一致 |
| 运行依赖检查 | PE 架构、导入 DLL、本地运行目录、系统目录 | 已扫描的直接/延迟导入满足规则 | 任意运行路径的动态加载 |
| 启动与连接 | 版本、启动、认证、X 根窗口查询、进程清理 | 最小 X 服务可使用 | OpenGL 正确性、输入法、剪贴板、多显示器 |
| 日常应用 | 实际 Linux 应用与 Windows 交互 | 指定版本、机器与场景下的行为 | 未测试的发行版、显卡和网络环境 |

测试结果使用 `PASS`、`FAIL`、`NOT_RUN`、`SKIP` 四种状态；跳过不等于通过。固定记录源码提交、工具版本、命令、退出码、日志路径和测试范围。机器完整日志放在本地忽略目录，提交经过检查的结果摘要。

## 持续关注的方向

| 方向 | 具体风险或问题 | 处理方式与触发条件 |
| --- | --- | --- |
| 工具链和 PATH | 开发机能运行，普通环境缺 DLL；误用另一个 Python/MSVC | 记录实际选中路径和版本；运行测试使用最小 PATH；工具升级后重跑第一阶段 |
| 第三方源码和预编译文件 | 仓库中同时存在源码和预编译依赖，例如 libxml2 | 建立来源、版本、补丁和构建方式清单；保留原版权与许可证材料；公开发布前核对随包材料 |
| 上游差异 | 本地修改与上游升级混在一起，难以合并和回退 | 本地 upstream 分支保存原作者快照，master 保存维护改动；旧历史另行归档；远程来源连接另行配置 |
| 生成器接口 | XKB 的 Meson 数据格式或 Python 脚本参数变化 | 更新相关组件时运行真实数据测试；解析不支持的格式时明确失败 |
| 运行目录更新 | 文件清单改变后旧 DLL 留存；运行中的 EXE 无法覆盖 | 基线从新目录组装；增量整理单独测试；失败报告源、目标和原因，不默默忽略 |
| 网络认证 | 为让测试通过而关闭访问控制，或修改机器防火墙 | 使用临时认证文件；不使用 `-ac`，不更改全局防火墙；测试只管理自己启动的进程 |
| 图形、输入和字体 | 显卡、缩放、键盘布局、中文显示/输入行为不同 | 第二阶段分别记录环境与结果；中文显示和中文输入分开验收 |
| 发布和版本 | 上游版本与自维护版本混淆，无法定位用户问题 | 第一阶段使用明确的本地标签；公开发布前设计自己的版本标识与发布说明 |
| CMake 迁移 | 同时替换全部构建规则导致故障难定位 | 完成基线后选一个边界清楚的组件试验；比较生成文件、链接依赖和运行结果 |

## 本地工作约定

- 文档、代码和验证结果在 Git 中保持关联；一次提交解决一个有意义的问题。
- 提交信息采用中文简短标题，空一行后用中文详细说明改动内容、原因和验证结果。
- 有行为变更时先建立针对原始问题的测试；纯文档变更检查链接、命令和覆盖关系即可。
- 执行第一阶段采用当前任务内顺序推进；独立审查可按适用技能安排，不要求维护者每一步重新授权。
- 规格范围改变、需要新增下载/安装、需要真实 Linux 环境或需要发布到远程时，说明具体需要再处理。
- 干净构建使用独立本地 worktree，保留主工作目录和已有运行目录。不使用全仓库 `git clean -xfd`。
- 本地 Git 历史不等于备份。远程仓库恢复可写或维护者确定备份位置后，再落实异地副本。
