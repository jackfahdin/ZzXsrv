## 起因与范围

维护者已确认前组 XSYNC/PRESENT/屏保候选“没问题”。合入前重跑 188 项检查时，真实启动验证再次超时；程序已启动，客户端持续收到认证数据无效的提示。此轮失败日志完整保存在主仓库 `.local-validation/sync-present-integration-20260911/` 所引用的候选证据中，没有靠重跑掩盖失败或直接合入。

用保持随机性的认证数据分别设置换行、CRLF、Ctrl+Z 片段，在前组 XKB 和当前 SYNC 产物上都复现了 CRLF 场景失败；普通数据通过。读取 xauth 实际输出的文件发现插入了额外字节，表明存在 Windows 文本模式转换。原生函数测试进一步区分了两个问题：

| 路径 | 原行为 | 修正 |
| --- | --- | --- |
| xauth 写文件 | `open` 未指定二进制模式，随后 `_fdopen(..., "wb")` 不改变底层描述符模式；写入时会扩展 LF | Windows 下在实际 `open` 时加 `O_BINARY`，保留独占创建和权限设置 |
| Server 读文件 | `Fopen(..., "r")` 会转换 CRLF，并把 Ctrl+Z 视为文本结束 | 使用 `"rb"` 原样读取字节；POSIX 行为不变 |

这两处是继承源码中的既有问题，不是前组同步修复新引入的变化。原组首次超时没有保留服务器日志，不能逐案追认根因；本次认证失败和字节变化有独立证据。
