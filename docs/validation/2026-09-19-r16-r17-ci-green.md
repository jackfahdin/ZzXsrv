## R17 与 CI 修复链（三个 fix 的根因 / 修复 / 验证）

CI 前三轮失败史：run 35296685944 与 35381508297 挂在 VS2022 缺失，run 35419591753 挂在 ISCC 相对路径；以下三个提交分别修复。

### runner 固定 windows-2022（`62e9f5eea8`，ci）

- 根因：windows-2025 runner 已换装 VS2026（18.x），`buildall.ps1` 经 vswhere `-version '[17.0,18.0)'` 解析编译器，找不到 VS2022 直接以 "VS2022 with the C++ x86/x64 tools is required." 秒挂。
- 修复：两个工作流 runner 固定为 windows-2022。VS2026 适配另行评估。

### 环境敏感测试修复 + xlaunch 中文路径真实产品 bug（`d890429a5f`，fix(r17)）

- `test_verify_runtime` 8.3 短名：GitHub runner 卷上启用了短名生成，`Path.resolve()` 可能冒出 `RUNNER~1` 形式的 8.3 短名导致 PATH 比较失败；修复在测试侧用 `GetLongPathNameW` 规范化后再比较。
- xlaunch 中文路径（真实产品 bug）：libwinmain 的 WinMain shim 把 argv 窄化到 ANSI 代码页分词，英文区域 Windows 上中文名配置文件无法表示而静默加载失败；修复为产品侧 `main.cc` 改用 `GetCommandLineW` + `CommandLineToArgvW` 取宽字符命令行并转 UTF-8 供 `-load`/`-run` 使用（libxml2 本就经 `_wfopen` 打开 UTF-8 路径）；测试 helper `xml_config.cpp` 同步改 `wmain` 传 UTF-8 文件名，使套件在任意 ANSI 代码页上都走真实加载路径。

### ISCC 相对路径绝对化（`02debbff17`，fix(ci)）

- 根因：ISCC 把相对 Source 路径相对 `.iss` 所在目录解析，CI 用 `--dist-dir dist/x64/Release` 调用时实际找的是 `installer\dist\x64\Release`，报 "No files found matching"。
- 修复：`package_release.py` 传给 ISCC 的 dist/输出路径先绝对化；新增对应打包测试。
