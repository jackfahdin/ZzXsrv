## 本轮修正与验证

生产代码仅修改 `src/c_client.py` 的一处分配表达式：原 Windows 适配把 `int fds[N]` 换成 `alloca(N)`，以元素个数分配字节。修正为 `alloca((N) * sizeof(*fds))`，括号也覆盖固定 FD 与可变列表相加的情况。不修改 socket 选项、协议 XML、公共头或 DLL 导出列表。

先通过真实生成器生成普通测试协议，再由 MSVC 编译运行其输出。单个 FD、四个 FD 列表、固定一个加可变两个各覆盖 checked/plain 两种调用；旧代码三项失败，新代码三项通过，分别为 0.395 秒和 0.341 秒。分配 hook 提供足够且对齐的物理存储，记录请求容量；传输边界 stub 检查容量、FD 顺序、checked 标记、cookie 和保护区，不执行旧代码的实际越界写入，也不连接服务器。这些是生成器契约测试，不是 Windows Unix FD 传送能力测试。

真实 SHM/DRI3 描述中共 10 个发送 FD wrapper 使用该生成路径；Windows 构建会编译相关生成文件，但继承 DEF 未导出这些请求。最终还需核对实际 DLL 导出；目前不声称存在当前产品可调用路径、日常故障或已实现 Unix FD 传送。

另增加五项实际 DLL/认证服务器消费者检查：TCP_NODELAY、SO_KEEPALIVE、根窗口几何、资源 ID 唯一性，以及 Xlib/XCB 共享根窗口与原子。旧 R9.1 产物五项均通过，3.473 秒，说明本机 socket 选项有效，保留相关继承代码。初版消费者缺少 pthread 头搜索路径，补齐现有工具链路径后完成实测；最终测试未模拟 socket、协议回复或 DLL API。

四份 NSIS 声明及历史 mkzip 增加 libxcb、xcb-proto 的 COPYING 与 libxcb 来源说明；本轮不执行安装或卸载。
