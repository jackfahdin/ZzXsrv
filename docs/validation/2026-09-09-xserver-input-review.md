## 生产差异与契约

`git diff` 确认，基线到候选的生产源码差异仅在 `xorg-server/os/io.c`：两处字数转字节前的上限判断，以及 `ignoreBytes` 未归零时不将输入缓冲区标为可共享。其余差异是测试与记录文件。

- `os/io.c:304` 与 `os/io.c:400` 均在 `needed <<= 2` 前检查 `needed > (MAXINT >> 2)`。两条异常分支都执行 `YieldControlDeath()` 并返回 `-1`，与此函数已有的分配失败、传输失败等终止分支一致。`YieldControlDeath()` 在 `os/io.c:200` 重置 `timesThisConnection`；该辅助函数自身不关闭连接。
- 函数说明在 `os/io.c:162` 至 `164` 将正值、零和负值分别定义为成功、尚未获得完整请求、终止客户端。实际调用方 `DispatchQueuedEvents` 在 `dix/dispatch.c:557` 调用解析器，随后对负值调用 `CloseDownClient(client)` 并退出内层循环（行 558 至 563），早于行 566 的 `requestBuffer` 访问。因此新增终止分支不要求先准备完整的 `requestBuffer`，也不再把未准备请求送入请求分发或错误回复流程。
- 基线与候选的 `dix/dispatch.c` blob 均为 `a2c612707e30c9645f61f4623720641a814e4443`，确认调用方已恢复为基线字节内容。只读搜索所得生产 C 调用点也位于该调用方。
- 两处判断对可表示长度均为假，后续既有路径不变；普通请求和有效 BigRequest 的解析、扩展头移动逻辑没有被改写。`MAXINT >> 2` 本身仍被允许，转为字节后可由正 `int` 表示。对可表示但超过服务器限制的长度，`os/io.c:320` 至 `328` 原有的正长度返回及 `ignoreBytes` 记录路径保留。本结论是“该路径未改动”，不是对该既有路径所有状态的独立正确性证明。
- `os/io.c:451` 新条件只在仍有待丢弃字节时阻止设置 `AvailableInput`；待丢弃字节归零后的空缓冲区仍可共享。`NextAvailableInput` 会清除上一次的全局可共享指针，因此本次处理不会沿用旧的共享标记绕开新条件。
