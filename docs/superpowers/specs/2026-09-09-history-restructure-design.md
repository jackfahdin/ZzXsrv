## 结构

将来源 `https://github.com/marchaesen/vcxsrv` 的提交 `d0a1eaf7ee15fcdf4f683388a88fec49078e6408` 文件树变为一个无父导入提交。导入正文使用中文，标注来源、日期、完整旧 SHA、版权与归档；不在纯快照中插入额外文件。

`upstream` 指向导入提交，今后以父子相连的快照提交记录原作者更新。`master` 从导入点派生，按顺序保留我们的六个提交及之后的维护改动。每个迁移提交的 tree、原作者元数据保持，标题与正文使用中文并写出旧提交号。当前完整旧历史保存在 bundle、恢复镜像和历史引用中；现有标签及证据 worktree 保留。

## 验收

1. 先从 bundle 恢复镜像，核对所有归档引用与 Git 对象连接，再创建新历史。
2. 导入树与原作者快照树一致，六个迁移提交逐项 tree 相等；迁移后首批链共七个提交、一个根。
3. 文档明确两层上游、更新优先级、快照导入与三方合并、直接组件更新、验证门槛、版权与来源记录。
4. 建立初始重要组件来源清单，区分原作者记录的同步点、开发版本、本地适配和未确认的预编译文件来源。
5. 文件树相等证明历史迁移没有改变源码；对新的 Git 提交运行 CheckOnly，核对环境报告来源。纯历史与文档变更无需重新编译，旧二进制仍引用真正的旧构建提交。
6. 独立审查、文档链接和 Git 差异检查通过，才切换主目录到新的 master；目录内原运行程序与构建证据保留。

## 边界与恢复

旧 master 归档引用为 `archive/pre-restructure-20260909`。新 master 不继续跟踪历史 GitCode origin/master；不更改远程地址、不推送、不强制更新远程。保留旧对象与标签，因此 Git 数据目录不一定变小；压缩的是新开发主线的历史。

新旧提交映射写入独立报告。旧基线标签不得移动到新 SHA，新 SHA 未经重新编译不得冒称为已重编译版本。后续组件更新和真实功能验证是独立工作。
